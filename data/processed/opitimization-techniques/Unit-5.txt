I. Introduction about Network Analysis:
Whenever dealing with a project like construction of building, introducing a new
product, or buying and installing a new machine, what come to mind includes
project completion deadlines, availability and requirement of resources for
activities to be done, the project costs…. so on. In fact, undertaking any project
requires breaking it down into constituent activities, establishing precedence
relationships between them (that is which activity will precede/succeed which
other activity or activities), time and resources needed for each activity, availability
of the resources and the costs involved.
PERT and CPM are the techniques which are available to a manager for getting
answers to question like the following
 Given the activities to be done in respect of a project along with time needed
for doing each one of them, how long the project will take to complete?
 By what date can the work on a particular stage of the project be expected
to be completed?
 What activities of the project can be delayed and by how much, while still
meeting the project completion deadline?
 What are the chances of completing the project by a certain due date?
 How best can the limited amounts of resources available be allocated to the
different activities so that the project can be completed at the earliest?
 How can the activities be scheduled so that variations in the demand of
resources may be reduced?
For, all in all, PERT and CPM are important and potent net work techniques
which have practical applications.

LST = LFT – duration of that activity.
8. Critical path: It is that sequence of activities which decides the total project
duration. Critical path is formed by critical activities. It is the longest path in
network and consumes maximum time and resources. A critical path has
zero float and expected completion dates cannot met, if even one critical
activity is delayed. A dummy activity joining the critical activities is also
critical activity.
9. Slack: It can be calculated by the difference between EFT and LFT for any
job. A job for which the slack time is zero is known as critical path.
10. Float: Float in the network analysis represent the difference between the
maximum time available to finish the activity and the time required to
complete it. There are so many activities where the maximum time available
to finish the activity is more than the total time required to complete it. This
difference is known as floats. Floats are three types are
1. Total float: It is the additional time which a non-critical activity can
consume without increasing the project duration. However, total float
may affect the floats in previous and subsequent activities.
2. Free float: It is that fraction from total float of an activity which can be
used for rescheduling the activity without affecting the succeeding
activity. If both tail and head events are given their earliest times. i.e EST
and EFT the free float can be calculated by deducting head slack
from total float.

IV. Rules for Network Diagram
1. Each defined activity is represented by one and only one arrow in the
network.
2. Before, an activity can be undertaken; all activities preceding it must be
completed.
3. The arrows depicting various activities are indicative of the logical
precedence only. The length and bearing of the arrows are of no
significance.
4. The arrow direction indicates the general progression in time. The arrow
head represents the point in time at which the ‘activity completion’ event
takes place, while arrow tail represents the point in time at which the event
‘activity start occurs’.
5. The event marking the start of activities are called tail events while those
marking the completion of activities are known as head events.
6. Events are identified by numbers. An effort should be made to have each
event identified by a number higher than that allotted to the event
immediately preceding. In assigning numbers to the events, care should be
taken that there is no duplication of event number in a network.
7. The activities are identified by a numbers of their starting and the ending
events. They are expressed as i-j where i represent the starting event, or
initial node, number and j represents the ending event, or the terminal node,
number.

VI. Fulkerson’s Rule:
Fulkerson’s rule is used to assign the numbers to the events. The procedure for
applying this rule consists of identifying the initial event and then gradually
converting the succeeding event by deleting the arrows from the previous
preceding events. A number is assigned only when by such deletions; a node is
converted into initial events.
The rule devised by Fulkerson’s is
1. An initial event is that which has arrows coming out of it, but none entering it.
There will be one such event in any network, numbering it 1.
2. Delete all arrows emerging out from event 1. This will create at least one more
Initial event, number this initial event as numbered 2.
3. Follow step (2) and number the new initial event as number 3. Continue until
Has last event is obtained, which has no arrow emerging out of it. (Forwarding
Events and activities identification in a network).

IX. CPM (Critical Path Method) :
One of the important objective of the network analysis is to know the minimum
possible time by which the project can be completed. This is done by determining
the critical path i.e the sequence of activities with longest duration. It is known as
critical path because any delay in activities lying on this path would cause a delay
in the whole project. To quicken the process, the activities lying on the critical path
should be taken first.
Critical Path Method (CPM) is a deterministic model, is based on the concept of
events, not probability. CPM methods can be applied with notable success to large
scale research and development programs. Ex: construction work, installation work
and industrial maintenance.
X. Steps in CPM (Identifying critical path) :
1. Dividing systematically the project into various activities.
2. Naming the activities.
3. Arranging all the activities in logical sequence.
4. Construction of arrow diagram.
5. The nodes (events) and activities to be numbered.
6. Finding time for each activity.
7. Marking activity time on the arrow diagram.
8. Early and late, start and finishing times to be calculated.
9. Tabulating various times and mark EST and LFT on the arrow diagram.
10. Calculation of total float for each activity.
11. Critical activities are to be identified and critical path marked on arrow
Diagram.
12. Total project time to be calculated.
13. Crashing critical activities of the network, in case the project durations is to be
reduced.
14. Optimizing the cost.
15. Smoothing network resources.
